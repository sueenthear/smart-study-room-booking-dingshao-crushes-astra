# evidence/ 测试与审查证据索引

本目录存放**精选证据**，每条证据一个文件，正文引用编号即可，不在报告里复制全文。

## 命名规则

| 前缀 | 用途 | 示例 |
| --- | --- | --- |
| `TC-U*.txt` | 单元测试执行原始输出 | `TC-U01_credit_rating_zero.txt` |
| `TC-I*.txt` | 集成测试执行原始输出 | `TC-I09_blacklist_require_date.txt` |
| `RV-*.md` | 交叉审查记录（模板 H） | `RV-01_PR4_取消预约修复.md` |
| `AC-*.md` | 阶段验收单（模板 I） | `AC-S1.md` |
| `AI-*.md` | 关键 AI 交互记录 | `AI-01_把已实现系统反推成需求条目.md` |

## 每条证据必须写清

```text
TC编号：
被测/场景：
代码版本（提交号）：
环境（OS / Python / uv / 数据库）：
命令（可直接复制的原始命令）：
结果（原始输出粘贴，含 OK / Ran N tests / FAILED 行）
备注（复用来源、未覆盖分支、失败原因）
```

## 硬性要求

1. **必须能复现**：写出提交号和命令，任何人 checkout 该提交后重跑应得到同样结果。
2. **不得只贴截图**：截图仅作辅助；并发、权限、异常类证据须有原始文本输出。
3. **不得伪造**：未执行的测试标"未执行"，失败标"失败"并写原因，不为凑数删断言。
4. **失败先判责**：实现不符则修实现；预期写错需依据并人工批准后改预期；需求冲突则重开 Q。
