## 1. 引言

### 1.1 目的

本文定义智慧自习室预约与管理系统的业务目标、系统范围、角色权限、功能需求、业务规则、数据要求、状态模型、非功能要求、验收场景和实施边界，作为课程评审、v2.0 开发、测试和验收的统一需求基线。

### 1.2 建设目标

| 编号 | 目标       | 可检验指标                          |
| -- | -------- | ------------------------------ |
| G1 | 座位可查可约   | 查询结果与实际占用一致；同一座位同一时段至多一条有效预约   |
| G2 | 规则自动执行   | 时长、次数、提前天数、取消、签到和超时未签到由系统按规则判定 |
| G3 | 异常可处置可追溯 | 违约、维修、投诉、黑名单及管理员代操作均有可查依据      |
| G4 | 运营可观测    | 提供预约趋势、区域分布、热门座位、爽约率和取消率统计     |

### 1.3 读者与用法

- 指导教师按第 3、5、6、7、9 章检查范围、规则和可验收性。
- 开发同学按第 4～8 章实现接口、服务、仓储和前端交互。
- 测试同学按第 9、10 章建立单元测试、集成测试和验收用例。
- 评审同学按第 11、12 章检查签字、证据和未关闭事项。

### 1.4 术语

| 术语     | 定义                                                   |
| ------ | ---------------------------------------------------- |
| 座位     | 可被单独预约的实体座位，隶属于某间教室                                  |
| 预约时段   | 起止时间，记为 `[start_at, end_at)`，左闭右开，统一使用 Asia/Shanghai |
| 有效预约   | 状态为 `booked` 或 `checked_in` 的预约                      |
| 座位实时状态 | 仅表示“此刻是否有人在用”，不表示“是否被人预约占位”                          |
| 受限账号   | 黑名单有效期内的账号：可登录、可查看、可申诉，不可创建预约                        |
| 取消率    | 统计周期内 `cancelled` 预约数 ÷ 已结束预约数，保留两位小数                |
| 候选功能   | 本期不纳入交付和验收，后续启用须另开变更记录                               |

## 2. 版本范围与系统边界

### 2.1 v2.0 的升级性质

v2.0 是**需求确认与架构加固版本**，不是全部推倒重写。范围必须区分三类：

| 类别     | 处理                                          |
| ------ | ------------------------------------------- |
| 沿用并验证  | 已存在的会话鉴权、并发串行化、座位状态机、信用规则、投诉与维修流程           |
| 补齐实现   | 定时扫描超时未签到、跨座位冲突、预约时长/次数/提前天数、过去时段校验、密码哈希与脱敏 |
| 新增需求口径 | BR-16～BR-21、权限与隐私决议、取消率统计、v2.0 分层与测试归属      |

### 2.2 范围内

| 范围项     | 本期口径                                               |
| ------- | -------------------------------------------------- |
| 账号与权限   | 本地账号登录；Bearer 会话；学生/管理员服务端权限隔离                     |
| 资源管理    | 教室、实体座位、座位实时状态、容量与开放状态自动汇总                         |
| 预约全生命周期 | 创建、查询、取消、签到、签退、违约、超时未签到                            |
| 预约规则    | 冲突、时长、每日次数、提前天数、过去时段、跨零点与签到窗口                      |
| 异常与反馈   | 座位报修/恢复、投诉/建议/申诉、管理员回复                             |
| 履约信用    | 5.0 基础分、每次违约扣 0.4、下限 1.0、90 天整笔剔除                  |
| 黑名单     | 原因、期限、强制解封日期、到期解封、受限账号不可预约                         |
| 运营统计    | 趋势、区域分布、热门座位、爽约率、取消率                               |
| 交付形态    | 本地 FastAPI + SQLite 可运行系统、自动化测试、GitHub Pages 静态说明页 |

### 2.3 范围外与候选功能

| 不做项             | 依据             | 后续处理                  |
| --------------- | -------------- | --------------------- |
| 定位、二维码、人脸等签到核验  | 需硬件、现场条件或算法服务  | 候选，本期不做               |
| 多次封禁自动转永久封禁     | 无业务制度依据        | 候选，本期不做               |
| 用户互评            | 与核心预约闭环无直接关系   | 候选，本期不做               |
| 投诉超时自动升级        | 本期无人力规则        | 候选，本期不做               |
| 学校统一身份认证（SSO）   | 无对接条件和凭据       | 本期仅预留身份来源接口，不实现真实 SSO |
| 短信、企业微信等外部通知    | 无渠道账号与凭据       | 本期只做站内可见状态            |
| 关闭教室并批量处置预约     | 牵出批量取消、通知和补偿规则 | 本期不做，FR-17 保持范围外      |
| 独立审计日志表、独立通知投递表 | 成本高于本期收益       | 不新增独立表；保留最小业务追溯       |
| 支付、押金、门禁、硬件联动   | 不属于本课程业务范围     | 明确不做                  |
| 原生移动客户端、离线能力    | 响应式网页已覆盖演示场景   | 明确不做                  |

### 2.4 系统边界

```text
学生 ─────────┐
              ├── Web SPA ── FastAPI ── SQLite
管理员 ───────┘                 │
                                ├── 定时扫描任务（v2.0 新增）
                                └── GitHub Pages（仅静态介绍页，不承载后端）
```

- 系统不连接真实教室硬件、校园身份平台或外部消息平台。
- GitHub Pages 只展示项目说明，不能代替后端运行环境。
- SQLite 只支持受控的单机写入部署，不支持多实例同时写同一数据库文件。

### 2.5 运行环境与技术约束

| 项  | 约束                                                     |
| -- | ------------------------------------------------------ |
| 后端 | Python 3.11+、FastAPI、Uvicorn                           |
| 数据 | SQLite 单文件；启动时自动建表与兼容迁移                                |
| 前端 | 原生 HTML/CSS/JavaScript 单页应用，响应式                        |
| 会话 | `auth_sessions` + Bearer token + sha256 摘要 + 12 小时 TTL |
| 部署 | 单机单进程；应用端口默认 `8000`                                    |
| 时区 | 统一 Asia/Shanghai，不允许跨零点预约                              |

### 4.2 创建预约的最终判定顺序

```text
身份有效
  → 账号未受限
  → 座位存在且非维修中
  → 时段格式合法且 end_at > start_at
  → 不跨零点
  → 学生预约：start_at 晚于当前时间 5 分钟以上
  → 单次时长 ≤ 4 小时
  → 同人当日预约 < 2 次
  → start_at 距当前日期 ≤ 7 天
  → 同座位无重叠有效预约
  → 同学生无重叠有效预约
  → 写入 booked
```

管理员补录可创建过去时段，但其余时长、次数、提前天数、冲突和跨零点规则仍适用；例外必须在接口审计信息中记录操作者。

## 5. 业务规则

### 5.1 沿用规则（BR-01～BR-15）

| 编号    | 最终规则                                   | 参数与边界                           | v2.0 状态                |
| ----- | -------------------------------------- | ------------------------------- | ---------------------- |
| BR-01 | 同一座位同一时段至多一条有效预约                       | 时段按左闭右开判断重叠                     | 已实现写事务串行化；数据库唯一约束待技术决策 |
| BR-02 | 同一学生同一时段不得有跨座位冲突预约                     | 任意两个 `booked/checked_in` 时段不得重叠 | 待实现                    |
| BR-03 | 维修中的座位不可预约                             | 座位 `maintenance` 时拒绝            | 已实现                    |
| BR-04 | 有活动预约的座位不可直接报修                         | 返回 409                          | 已实现                    |
| BR-05 | 预约状态只能沿允许路径迁移                          | 见第 7 章                          | 已实现                    |
| BR-06 | 取消只允许发生在 `booked`                      | 开始后是否允许取消仍按 ST-02 判定            | 已实现状态限制；时间边界待补         |
| BR-07 | 迟到超过 15 分钟登记违约                         | 恰好 15 分 00 秒不违约；15 分 01 秒违约     | 已实现                    |
| BR-08 | 早退只记录分钟数，不扣信用分                         | 记录 `early_minutes`              | 已实现                    |

## 6. 数据需求

### 6.1 核心数据表

| 数据表             | 主要字段                        | 用途     | v2.0 约束                         |
| --------------- | --------------------------- | ------ | ------------------------------- |
| `users`         | 姓名、学号、手机号、密码、违约次数、信用分、黑名单信息 | 账号与信用  | 学号唯一；密码哈希；响应不回传密码               |
| `auth_sessions` | token 摘要、用户、角色、过期时间         | 服务端会话  | 12 小时 TTL；登出后失效                 |
| `classrooms`    | 名称、楼栋、楼层、容量、状态、设施           | 教室资源   | 容量由座位汇总                         |
| `rooms`         | 编号、教室、状态、设施、维修说明            | 实体座位   | 状态仅 `open/occupied/maintenance` |
| `bookings`      | 用户、座位、起止时间、状态、签到/签退、迟到/早退   | 预约生命周期 | 时段合法、不跨零点、冲突受控                  |
| `complaints`    | 用户、座位、分类、主题、内容、状态、回复        | 反馈处理   | 分类受控；学生只能看本人                    |
| `violations`    | 用户、预约、原因、来源、时间              | 信用依据   | 同一预约不重复生成同一违约                   |

### 6.2 数据规则

1. 时间统一保存为 ISO 8601 带时区字符串；业务比较统一转换到 Asia/Shanghai。
2. 预约必须满足 `end_at > start_at`，且起止时间位于同一自然日。
3. 同一座位同一时段只允许一条有效预约；v2.0 维持写事务串行化，唯一索引另行技术决策。
4. 同一学生任意两笔有效预约的时段不得重叠，即使座位不同。
5. 密码使用不可逆哈希；日志、接口响应和 CSV 导出不得含明文密码。
6. 学生侧手机号中间四位掩码，例如 `158****9033`。
7. 数据保留期为本学期交付周期；到期后删除或匿名化，不含日志中的手机号与密码。

## 7. 状态模型

### 7.1 预约状态

```text
booked ──签到──> checked_in ──签退──> completed
  │                 │
  │                 └──使用异常──> violation
  ├──取消──> cancelled
  └──超时未签到──> violation
```

五态：`booked`、`checked_in`、`completed`、`cancelled`、`violation`。

| 编号    | 当前态          | 事件       | 执行角色   | 最终条件                               | 目标与结果                                    |
| ----- | ------------ | -------- | ------ | ---------------------------------- | ---------------------------------------- |
| ST-01 | 无            | 创建预约     | 学生/管理员 | 满足第 4.2 节全部校验                      | `booked`，占用该时段                           |
| ST-02 | `booked`     | 取消       | 学生/管理员 | 仍在允许取消的时间边界内                       | `cancelled`；只释放时段，不改座位实时状态               |
| ST-03 | `booked`     | 签到       | 学生/管理员 | 开始前 30 分钟至结束时间之间；超过开始 15 分钟可签到但记违约 | `checked_in`，座位 `occupied`               |
| ST-04 | `booked`     | 宽限期届满未签到 | 系统     | 开始后超过 15 分钟仍为 `booked`             | `violation`，释放时段占用并扣 0.4                 |
| ST-05 | `checked_in` | 签退       | 学生/管理员 | 结束前签退；超时按结束时间归档                    | `completed`，记录 `early_minutes`，座位 `open` |
| ST-06 | `checked_in` | 使用异常     | 管理员    | 维修、清场等有明确原因                        | `violation`，记录原因，座位按实时占用恢复               |
| ST-07 | `booked`     | 管理员代取消   | 管理员    | 教室关闭、设备故障等                         | `cancelled`，必须记录原因并在站内显示                 |
| ST-08 | `completed`  | 任意回退     | 任意     | 终态不可回退                             | 拒绝                                       |
| ST-09 | `cancelled`  | 签到       | 任意     | 取消记录无有效占位依据                        | 拒绝                                       |


### 7.2 座位状态

| 编号    | 当前态           | 事件       | 执行角色      | 条件                    | 目标态           |
| ----- | ------------- | -------- | --------- | --------------------- | ------------- |
| ST-10 | `open`        | 签到成功     | 学生/管理员    | 对应预约 `booked`         | `occupied`    |
| ST-11 | `occupied`    | 签退、违约或结束 | 学生/管理员/系统 | 当前预约终止，且无其他已签到预约占用该座位 | `open`        |
| ST-12 | `open`        | 报修       | 管理员       | 无活动预约                 | `maintenance` |
| ST-13 | `maintenance` | 维修完成     | 管理员       | 填写恢复说明                | `open`        |
| ST-14 | `maintenance` | 再次报修     | 管理员       | 已处于维修中                | 状态保持，不重复登记    |

### 7.3 状态语义约束

- 座位状态是**实时使用状态**，不是预约占位状态；创建未来预约不会把座位改为 `occupied`。
- 取消未来预约不得把同一座位当前已签到的 `occupied` 改回 `open`。
- `cancelled` 只表示预约终止，不代表座位实时状态变化。
- `violation` 是预约终态，同一预约只允许生成一次对应违约。

## 8. 接口与系统设计

### 8.1 分层约束

v2.0 采用以下职责边界，支撑每人约 20 个单元测试和 10 个集成测试：

| 层   | 职责                  | 不允许       |
| --- | ------------------- | --------- |
| 路由层 | 参数解析、身份依赖、状态码、响应模型  | 承载复杂业务判定  |
| 服务层 | 预约、资源、用户与信用、反馈与统计规则 | 直接拼 SQL   |
| 仓储层 | SQL、事务、查询、持久化映射     | 决定业务优先级   |
| 公共层 | 鉴权、数据库、错误码、时间       | 承载单一业务域规则 |

业务按四域归属：预约、资源、用户与信用、反馈与统计。四人各认一域并对该域的测试负责。

### 8.2 关键接口清单

| 能力         | 方法与路径                                                                          | 主要权限        |
| ---------- | ------------------------------------------------------------------------------ | ----------- |
| 登录/登出/当前会话 | `POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`              | 公开/持 Token  |
| 总览与统计      | `GET /api/overview`、`GET /api/analytics`                                       | 管理员         |
| 教室管理       | `GET/POST/PATCH/DELETE /api/classrooms`                                        | 查询公开；写操作管理员 |
| 座位查询与状态    | `GET /api/rooms`、`PATCH /api/rooms/{id}/status`                                | 查询公开；修改管理员  |
| 预约管理       | `GET/POST/PATCH /api/bookings`                                                 | 学生本人；管理员全部  |
| 用户、账号与信用   | `/api/users`、`/api/users/{id}/account-status`、`/api/users/{id}/credit-profile` | 本人或管理员      |
| 违约记录       | `/api/violations`                                                              | 管理员         |
| 投诉反馈       | `/api/complaints` 相关接口                                                         | 学生本人；管理员处理  |
| CSV 导入     | `POST /api/users/import`                                                       | 管理员         |

### 8.3 接口约定

| 场景             | 约定              |
| -------------- | --------------- |
| 未登录或 Token 无效  | 401             |
| 已登录但无权限        | 403             |
| 输入格式错误或必填项缺失   | 400/422，按错误类型统一 |
| 预约冲突、维修冲突、重复状态 | 409             |
| 写锁竞争           | 503，客户端可合法重试    |
| 成功创建           | 201             |
| 查询成功           | 200             |
| 删除成功           | 204             |

### 8.4 前端与部署

- 登录结果保存在 `localStorage.studySession`，401 时清理会话并返回登录页。
- 页面每 10 秒刷新；用户正在编辑表单时不得覆盖输入。
- 所有动态标题、姓名和学号必须转义，禁止把接口字段直接拼入 `innerHTML`。
- GitHub Pages 只发布 v2.0 静态说明页；后端必须单独运行。
