# 功能文档审查与优化记录

审查依据：《可能需要的功能.docx》及其中的座位状态流程图。

## 总体结论

项目已经覆盖文档提出的核心业务闭环：座位资源、预约、取消、签到、签退、违约、查询、管理员操作、信用分、投诉反馈、黑名单和数据分析。

本次审查重点补齐了此前不够明确的行为规则。

## 功能对照

| 文档要求 | 当前实现 |
| --- | --- |
| 座位属性与状态 | 可预约、使用中、维修中三种实时状态，并保留状态说明和更新时间 |
| 座位查询 | 支持按名称、区域和设施搜索，支持状态筛选 |
| 座位预约记录 | 每个座位均可打开最近预约记录 |
| 预约与冲突 | 同一座位同一时段只允许一条有效预约，时段重叠会被后端拒绝 |
| 取消预约 | 仅已预约状态可取消，取消后释放座位 |
| 签到与签退 | 记录实际签到、签退时间；签到超过 15 分钟自动登记迟到违约 |
| 早退记录 | 签退时记录提前分钟数，不自动扣信用分 |
| 管理员代办 | 管理员可在预约管理中代替用户签到、签退、取消或登记违约 |
| 自动违约 | 系统在迟到签到、未签到违约和异常使用时生成违约记录并同步信用分 |
| 履约信用分 | 基准 5.0，每次违约扣 0.4，最低 1.0 |
| 信用恢复 | 违约记录满 90 天后自动失效，信用分随时间恢复 |
| 黑名单通知 | 学生登录后可见限制原因、限制时间和解封倒计时 |
| 投诉反馈 | 支持投诉、报修、建议和账号申诉，并可关联具体座位 |
| 管理端处理 | 投诉状态与回复会同步显示给学生 |
| 数据分析 | 保留预约趋势和区域分布，新增热门座位排行和爽约率 |

## 规则说明

### 座位状态

- 可预约：当前允许创建预约。
- 使用中：已有用户签到使用。
- 维修中：暂停预约，必须完成维修后才能恢复。
- 有未结束预约的座位不能直接报修，需先取消或调整预约。

### 信用分

- 基础分：5.0。
- 每次有效违约：扣除 0.4 分。
- 最低分：1.0。
- 违约记录满 90 天后自动退出信用扣分范围。
- 迟到签到超过 15 分钟会生成一条系统违约记录。
- 早退只记录分钟数，暂不自动扣分。

### 数据分析

- 热门座位按有效预约次数排序。
- 取消预约不计入热门排行。
- 爽约率按违约预约占有效预约的比例计算。

## 暂未实现的扩展建议

以下内容在文档中属于探索性建议，当前版本没有强行加入：

- 定位、二维码或校园统一身份认证签到。
- 定时任务自动扫描所有超时未签到预约。
- 多次封禁后自动转为永久封禁。
- 用户之间互相评分。
- 投诉响应超时自动升级和临时关闭投诉权限。

当前选择履约信用分而不是学生互评，是因为同学之间没有稳定的服务关系，互评更容易产生主观评分和恶意评价。
